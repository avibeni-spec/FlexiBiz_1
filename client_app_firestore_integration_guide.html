# FlexiBiz Client App - Firestore & Logic Integration Guide This document outlines how to connect the luxury client-facing app to your Firebase backend. ## 1. Authentication (Client Context) For a personalized experience, we assume the use of `firebase_auth`. - **Current User:** `ref.watch(authStateProvider).value?.uid` - **Booking Ownership:** Every appointment created by a client will include their `clientId`. ## 2. Real-time Service Catalog Instead of hardcoded services, the app will now pull from the `services` collection in Firestore. ```dart final servicesStreamProvider = StreamProvider>((ref) { return FirebaseFirestore.instance.collection('services').snapshots().map( (snap) => snap.docs.map((doc) => Service.fromMap(doc.data())).toList() ); }); ``` ## 3. The Booking Workflow 1. **Service Selection:** Client chooses a service (ID passed to next screen). 2. **Availability Check:** The `ChooseTimeScreen` queries existing appointments for the selected date to hide busy slots. 3. **Creation:** A new document is added to the `appointments` collection with `status: "scheduled"`. ## 4. Client Timeline (`My Appointments`) We use a specific query to show only the logged-in client's visits. ```dart final clientAppointmentsProvider = StreamProvider>((ref) { final uid = ref.watch(userIdProvider); return FirebaseFirestore.instance .collection('appointments') .where('clientId', isEqualTo: uid) .orderBy('dateTime', descending: true) .snapshots() .map((snap) => snap.docs.map((doc) => Appointment.fromMap(doc.data())).toList()); }); ``` ## 5. Design Consistency All screens continue to use the **Onyx & Alabaster** theme tokens implemented in `ThemeData`.
