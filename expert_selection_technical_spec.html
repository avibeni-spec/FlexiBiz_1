# FlexiBiz - Expert Selection Technical Specification ## 1. Data Model: Specialist Each expert/specialist will be represented by a `Specialist` model in Firestore. ```dart class Specialist { final String id; final String name; final String role; // e.g., 'Senior Aesthetician', 'Master Stylist' final String imageUrl; final String bio; final double rating; final List expertise; // e.g., ['Facials', 'Peels'] final Map availability; // Simplified schedule Specialist({ required this.id, required this.name, required this.role, required this.imageUrl, this.bio = '', this.rating = 5.0, this.expertise = const [], this.availability = const {}, }); Map toMap() => { 'id': id, 'name': name, 'role': role, 'imageUrl': imageUrl, 'bio': bio, 'rating': rating, 'expertise': expertise, 'availability': availability, }; factory Specialist.fromMap(Map map) => Specialist( id: map['id'], name: map['name'], role: map['role'], imageUrl: map['imageUrl'], bio: map['bio'] ?? '', rating: (map['rating'] ?? 5.0).toDouble(), expertise: List.from(map['expertise'] ?? []), availability: Map.from(map['availability'] ?? {}), ); } ``` ## 2. Firestore Integration We will add a `specialists` collection to Firestore. ```dart // logic/providers/database_providers.dart final specialistsStreamProvider = StreamProvider>((ref) { return FirebaseFirestore.instance.collection('specialists').snapshots().map( (snap) => snap.docs.map((doc) => Specialist.fromMap(doc.data())).toList() ); }); ``` ## 3. Booking Logic Update When a client selects an expert, the `specialistId` will be passed through the booking flow and stored in the `Appointment` document. ```dart // Update Appointment Model class Appointment { // ... existing fields final String? specialistId; // Link to the chosen expert Appointment({ // ... existing fields this.specialistId, }); } ```
